# Own vocabulary based on schema.org

No open standard covers resource allocation. schema.org, iCalendar, HR Open, OAGIS and EDIFACT each cover a part at most. We define our own JSON vocabulary for the API and for later CloudEvents payloads, styled on schema.org. A field uses the schema.org property name where the meaning matches exactly (`name`, `email`, `startDate`, `endDate`, `dateModified`), and our own camelCase name otherwise (`percentage`, `isPlanner`). Each object has a `type` field with its glossary name (`Person`, `Allocation`). Ids are UUIDv7, generated by the server. Dates are `YYYY-MM-DD`, and end dates are inclusive. Timestamps are RFC 3339 in UTC.

## Consequences

- v1 uses plain JSON without a JSON-LD `@context`. A context can come later, together with a schema published at a stable URL.
- An iCalendar export must add one day to each end date, because iCalendar end dates are exclusive.
- Field names become a contract once integrations exist. Change them only with a new schema version.
